# Kayıt Keşfi

Kaynak: [`docs/workflow/33-record-discovery/phase-context.md`](../../workflow/33-record-discovery/phase-context.md)

## Problem Statement

Kurucu yetkili ana kayıtları, Belgeleri ve Dosya Eki üstverisini deterministik tam metinle, neden bulunduğunu görerek yerinde bulmak ister. Bugün arama AI sıralar, Taslak/yakalama/dış yüzey/secret indekslenir, Komut Paleti ile tek yüzey sanılır, önizleme ikinci kayıt olur, hazır dizin kurulumsuz değildir veya tablo satırı ayrı sistem olur. Akıllı Koleksiyon üyeliği ve palet komutları bu sorunun parçası değildir.

## Solution

Evrensel Arama yetkili ana kayıtları kapalı eşitlik-bozucu sırayla bulur; eşleşme bağlamı görünürdür. Taslak, Yakalama öğesi, Dış yüzey, GitHub dış kaydı ve secret dizinlenmez. Hazır tür dizinleri sıfır kurulumla gezer. Tür-kapsamlı Table, izinli türlerde aynı ana kayda inline yazar. Desteklenen yüzeylerden geçici önizleme kaynak bağlamını korur. Filtrelenmiş aramayı koleksiyon olarak kaydetmek 34’ün oluşturma eylemidir; bu feature komutu açar, üyeliği tanımlamaz.

## User Stories

1. As a founder, I want `Search` to find authorized main records with deterministic full-text order and visible match context, so that I know why a hit appeared.
2. As a founder, I want Document bodies and File Attachment metadata in that same authorized set, so that knowledge is not a separate library.
3. As a founder, I do not want AI, learned, click-history, or semantic ranking, so that the six-step tie-break table is the only order.
4. As a founder, I want title/key matches before body, current Project before others, active before closed, `Completed` before `Abandoned`, then recency, then stable id, so that repeats of the same query are identical.
5. As a founder, I want archived records only with an explicit archive filter, and never Trash or unauthorized records, so that search cannot leak or resurrect.
6. As a founder, I want result badges for type, status, closure outcome if any, and scope, so that I can tell what I found.
7. As a founder, I want a short match snippet, term highlight, and match count from an indexed source I can access, so that badges say what it is and the snippet says why.
8. As a founder opening a hit, I want to land on the match location when the type supports it, so that I am not dumped at the top of a long Document without explanation when location is unsupported.
9. As a founder, I do not want Drafts, Capture Inbox items, External Surfaces, or GitHub external records in Search, so that temporary and visitor surfaces stay on their own screens.
10. As a founder, I do not want secrets, share tokens, or link passwords indexed, so that discovery cannot become a secret oracle.
11. As a founder, I want limited operators that match visible filters, with autocomplete into filter chips, so that power users are not given a hidden query language.
12. As a founder, I do not want a temporary filtered search to become a Smart Collection by itself, so that collection create stays workflow 34’s command; this feature may later open that command as a counterpart and must not store membership.
13. As a founder, I do not want Search to be the Command Palette, so that commands and records stay two surfaces.
14. As a founder, I want zero-setup indexes such as `All Work`, `All Documents`, `All Decisions`, `All Risks`, `All Research Sessions`, `All Tests`, `All Designs`, `All Technical Diagrams`, `All Project Releases`, `All Sources`, and `All Files`, so that I can browse a type without building a collection.
15. As a founder, I want those indexes to collect existing main records of that type only—no stored query—and to keep each record in its Project or Wiki scope, so that an index is not a new ownership. Document and File Attachment indexes browse by scope, type, folder, and supported metadata on that same prepared surface; folder is not a second library and not a replacement for Search.
16. As a founder, I want `All Files` to show each File Attachment once, with older versions in the attachment’s history, so that indexes are not version spam.
17. As a founder, I want type-scoped `Table` with inline cell edit only for types the closed matrix allows, so that Documents are searchable but not table-edited, and screens/diagrams/attachments are not Smart Collection sources.
18. As a founder pasting multiple rows, I want column mapping and an all-or-nothing apply, so that Table is not a silent spreadsheet sync.
19. As a founder, I want in-context preview from Kanban, Unified Calendar, Roadmap, Scope Tree, Smart Collection, and Notification Center via the same `Open source record` defaulting to a temporary side panel, so that I can read without losing my place.
20. As a founder, I want `Open full page` for deep work, and I do not want the panel or its inner navigation restored as recent-context, so that preview is not a layout.
21. As a founder, I do not want a mandatory side panel on every record type, so that preview stays opt-in per supported surface.
22. As a founder, I want English UI copy for `Search`, the `All …` indexes, `Table`, `Open source record`, and `Open full page`, so that the product language stays English.
23. As a founder using only a keyboard or a screen reader, I want to search, filter, open a hit, use an index, edit an allowed table cell, and preview, so that Arama ve ilişki is possible without a pointer-only palette.
24. As a founder, I do not want this feature to own Smart Collection membership rules, custom-field schemas, or Command Palette actions.

## Implementation Decisions

- **Owning documents.** Behavior is owned by [Evrensel Arama](../../prd/08-search-relations-and-evidence.md#evrensel-arama), [çalışma alanı genelindeki hazır tür dizinleri](../../prd/08-search-relations-and-evidence.md#çalışma-alanı-genelindeki-hazır-tür-dizinleri), [tür-kapsamlı Table görünümü](../../prd/08-search-relations-and-evidence.md#tür-kapsamlı-table-görünümü), and [bağlam içi kayıt önizleme](../../prd/08-search-relations-and-evidence.md#bağlam-içi-kayıt-önizleme). Secret-not-in-search is the security/portability secret rule. Free advanced query language ban is [PRD 19](../../prd/19-out-of-scope.md). Command Palette is [PRD 04](../../prd/04-workspace-and-projects.md#komut-paleti-ve-klavye-odaklı-kullanım) / workflow 05. Stack: `pg_trgm` and TanStack Table as adapters behind this seam, not ranking policy. Multi-row atomic/idempotent writes follow [ADR 0004](../../adr/0004-atomik-idempotent-kesinlestirme.md); no new ADR.
- **Glossary.** Use Evrensel Arama (`Search`), Kayıt Keşfi, Taslak, Yakalama Gelen Kutusu öğesi, Dış yüzey, Komut Paleti (not this), Akıllı Koleksiyon (save action hands off to 34), Tablo Görünümü (`Table`). Do not introduce AI search, semantic rank, or a second document library.
- **Ranking.** Apply the PRD’s closed tie-break table in order. No extra signal. User-visible filters may override default order with explicit date/text sorts. Live results as query/filter change; that state is temporary until saved as a collection via 34.
- **Index exclusions.** Not indexed: Capture items, Drafts, External Surfaces, GitHub external records, secrets, share tokens, link passwords, generated SQL bodies (diagrams). Generated Migration Artifact user-facing names may be found via the owning Technical Diagram, not as independent hits.
- **Indexes.** Zero-setup, type selector, not per-type main nav. Closed list: `All Work`, `All Documents`, `All Decisions`, `All Risks`, `All Research Sessions`, `All Tests`, `All Designs`, `All Technical Diagrams`, `All Project Releases`, `All Sources`, `All Files`. `All Tests` keeps Planned Test Case, Test Handoff, Test Session, Session Test, Test Gap, and Test assessment distinct. `All Technical Diagrams` keeps Technical Architecture, Data Model, Technical Sequence, and Diagram authority mode distinct. Archive stays findable with filter; not treated as deleted. Document and File Attachment indexes use the same prepared surface with scope, type, folder, and supported metadata; folder is navigation, not ownership, and does not replace Universal Search. `All Research Sessions`, `All Tests`, `All Designs`, and `All Sources` remain empty until their canonical record models exist; this issue adds no schema or new ownership for them.
- **Table matrix.** Honor the closed type × surface matrix (PRD 08): Work, Project Goal, Milestone, Project Release, Feedback, Contact, Company, User Research Session, Decision, Risk, Assumption, Open Question, Product Gap, Source, Planned Test Case, Test Handoff, Test Session, Test Gap, Test assessment, Production Incident → Table+inline and Smart Collection source. For #267, implement only Work and the existing Project source owners Decision, Risk, Assumption, Open Question, Milestone, Project Release, and Production Incident; other matrix types remain out of this delivery until their canonical owners exist. Document/Wiki Document → search/index yes, Table+inline no, Smart Collection source on structured metadata/tags/scope only. Screen, User Flow, Project Wall, Moodboard, Technical Diagram, File Attachment → search/index yes, Table+inline no, Smart Collection source no. Capture Inbox item, Draft, External Surface, GitHub external record → not in Search/Table/collection source. Inline edit is not bulk edit (22). Session Test results are not written from the cell except via the test-correction event owned elsewhere.
- **Preview.** Kayıt Keşfi `Open source record` geçici panelini Kanban, Unified Calendar, Roadmap, Scope Tree ve Smart Collection tüketicilerine sağlar; derin çalışma için `Open full page` vardır. Notification Center entegrasyonu, yüzeyin UI ve route sahipliği olan `docs/specs/72-personal-shell/` kapsamındadır ve hazır olduğunda aynı önizleme davranışını kullanır. Kaynak kopyası veya kalıcı panel düzeni oluşturulmaz.
- **Save as collection.** Out of this feature. Workflow 34 owns create. Temporary search never persists membership. A later counterpart may open 34’s command from this search; this seam does not define collection rules.
- **English UI labels.** `Search`, `All Work`, `All Documents`, `All Decisions`, `All Risks`, `All Research Sessions`, `All Tests`, `All Designs`, `All Technical Diagrams`, `All Project Releases`, `All Sources`, `All Files`, `All Projects`, `No records in this index.`, `Table`, `Type`, `Project`, `Filter rows`, `Paste rows`, `Preview paste`, `Column mapping`, `Skip column`, `Record ID`, `Review paste`, `Correct row`, `Exclude row`, `Include row`, `Apply changes`, `No matching records.`, `Changes applied.`, `Applying changes…`, `Table is unavailable.`, `Open source record`, `Open full page`, `Loading document preview…`, `Temporary preview that keeps the current source view in place.`. Table field, accessible-control, validation, and status labels follow the PRD term table. Missing labels join the PRD term table in the same change that first shows them. No Turkish UI. `Save as Smart Collection` is 34.

## Testing Decisions

- **Next concrete step discovery (#293).** `Search` güncel Proje ve İşin aynı `Next concrete step` alanını kullanır. Proje adı/kısa kod eşleşmesi mevcut başlık/anahtar sırasına, adım eşleşmesi gövde sırasına uyar. Hesap, scope, type ve archive sınırları korunur; Proje sonucu kendi `Overview` kaynağına gider. `universal-search-database.test.ts` değiştirilmiş adımın bulunmamasını ve Proje erişim/scope/archive sınırlarını; `universal-search-results.test.tsx` Proje kaynak bağlantısını doğrular. Yeni index veya ayrı adım kaydı oluşturulmaz.

- **Document consumer delivery (#242).** The founder chrome's `Search` dialog exposes Universal Search and a shared `Discovery view` selector with `Search` / `All Documents`. `Search` uses the mixed-record `Search results` list; the `All Documents` index owns the Document-only scope/type/folder controls. It is separate from the Command Palette and adds no per-index main navigation route. `Scope` offers `All scopes`, `Personal Wiki`, and exact `Project: <project name>` options; `Type`, `Folder`, and `Archived` remain temporary. `Archived` selects only archived Documents or Documents in archived Projects; their result status is `Archived`. `All types` and `All folders` clear those filters. PostgreSQL's built-in deterministic text query over authorized Document title/body supplies this consumer without a persistent saved query or a new ownership table; no schema/extension change is needed. Universal Search across other persisted record families is delivered by #264; other indexes, Table, collection commands and shared preview consumers remain separate work outside #242's scope. This section is tested by the Document counterpart evidence below.
- **Document counterpart evidence (#242).** `apps/server/src/features/documents/server/documents-database.test.ts` observes `discoverDocuments` through public RPCs: same-title Wiki/Project hits, authorized scope/type/Folder/Archive filters, title-before-body, current Project before other homes, stable repeated ordering, match context/count and Account isolation. `documents-rpc.test.ts` denies unauthenticated requests before reading discovery. `apps/web/src/utils/orpc.test.ts` verifies Account-specific discovery cache keys and disabled anonymous queries. `apps/web/src/features/record-discovery/ui/components/universal-search-results.test.tsx` observes badges, safely rendered term highlights and canonical links; `apps/web/e2e/document-discovery.e2e.ts` requires a successful `searchRecords` response from the real database adapter in the E2E server, verifies mixed Wiki/Project body matches and highlights in `Search results`, applies scope filters in `All Documents`, opens canonical homes from both surfaces and verifies temporary query/view/scope reset. The Personal Wiki scope tests remain the owning evidence for the home distinction. This is local regression evidence, not universal all-family search acceptance.

- **Universal Search evidence (#264).** `apps/server/src/features/record-discovery/server/universal-search-database.test.ts` observes all currently persisted Search record types through the public RPC, the six-step deterministic order, repeatable results, Account isolation, archive and Trash exclusion, Document body matches, only-current File Attachment metadata, and Technical Diagram view/node labels. `universal-search-rpc.test.ts` verifies the authenticated Account is the search principal and unauthenticated requests stop before reading records. `apps/web/src/utils/orpc.test.ts` verifies Account-specific Search cache keys; `apps/web/src/features/record-discovery/ui/components/universal-search-results.test.tsx` verifies type/status/closure/scope badges, escaped highlights, match count, and canonical source links. These tests bind the Universal Search behavior to the Record Discovery seam; database execution remains subject to the configured development database readiness contract.

- **Prepared type indexes (#266).** The `Discovery view` selector exposes the closed eleven-index list. Existing canonical models back `All Work`, `All Documents`, `All Decisions`, `All Risks`, `All Technical Diagrams`, `All Project Releases`, and `All Files`; the four indexes without canonical models return no rows. `universal-search-database.test.ts` observes empty-query index reads through public `searchRecords`, including scope and archive selection, and confirms the four empty indexes return no rows while each of the seven implemented indexes has a seeded row. Its Document and File Attachment fixtures verify scope, type, Folder, Archive, and one current attachment version. `document-discovery.test.ts` verifies the closed selector labels, their accepted values, and the `No records in this index.` empty state. `universal-search-results.test.tsx` verifies index metadata and `Open source record` without Search-only snippets or match counts. No database schema or ownership is added; database execution remains subject to the configured development database readiness contract.

- **Exclusion matrix evidence (#265).** `apps/server/src/features/record-discovery/server/universal-search-database.test.ts` seeds unique Capture Inbox, Work Draft, and External Surface snapshot canaries plus synthetic Better Auth session/provider Account credentials and Capture Extension token/pairing-code hashes. It queries the public `searchRecords` seam for each canary, checks returned serialization for credential values, and separately asserts that Capture Inbox, Draft, External Surface, GitHub external, and Migration Artifact are each absent from the supported Search record types. A Technical Diagram node label remains searchable through its owning Technical Diagram. The same seam verifies that a File Attachment in Archive is hidden by default and included with the explicit archive filter, while Trash stays hidden with either archive-filter value; the #264 fixture also proves Work Trash exclusion and Account authorization. GitHub external records have no local table or Search adapter in the current schema, so their exclusion is represented by the closed Search type set. Current schema also has no dedicated External Surface share-token/link-password fields or persisted Migration Artifact SQL body: share-token/link-password canaries remain ordinary text in the excluded Capture Inbox fixture, and generated SQL has no DB-backed search fixture. Only diagram view names and node labels are observed as searchable (#264 and the node-label query above); the diagram's type, authority mode, and link labels stay in its indexed text without a dedicated search assertion. Do not treat ordinary-text canaries as proof about absent credential columns; revisit those fields if their owning schema is introduced.

- **Type-scoped Table evidence (#267).** The implemented Table source set is limited to existing canonical owners: Work and Project source records Decision, Risk, Assumption, Open Question, Milestone, Project Release, and Production Incident. Record Discovery public RPC tests observe listing, allowed cell writes, paste inputs and results, account and scope authorization, and atomic/idempotent application against those same owner records. Rendered `Table` UI tests observe one-type scope, sorting, filtering, column-to-field mapping preview, invalid-cell handling, and explicit row correction/exclusion before apply; `apps/web/e2e/record-table.e2e.ts` observes the rendered correction/exclusion path and retries an apply after its first committed response is lost. Database integration tests exercise list, write, and paste through the public Record Discovery RPC and observe persisted outcomes by reading through that RPC, rather than asserting private database helpers. No additional type owner, schema, migration, row identity, or Smart Collection membership is introduced.

- **Document selection control evidence (#242).** `apps/web/src/features/record-discovery/ui/components/document-discovery.test.ts` verifies exact scope selection round trips and rejects invalid scope/view values before they become a query. It complements the live filter behavior above without creating a saved view or changing Document ownership.

- **Context preview evidence (#268).** `apps/web/src/features/record-discovery/ui/components/context-record-preview.test.tsx` verifies the shared action's accessible name, a preview panel title that names the opened record instead of repeating the action label, canonical full-page destinations for Work, Project source records, Project Documents and Wiki Documents, and a temporary Work preview with its description, `Horizon`, archive state and full-page action but no collection-creation controls. Its Document preview case verifies live Work actions and supported in-document Work references use the preview action without direct source navigation; a link that navigates away calls the panel close handler. `apps/web/src/features/project-source-records/ui/components/project-source-record-view.test.tsx` verifies read-only source records omit personal-reminder actions. The Kanban, Unified Calendar, Scope Tree, Roadmap and Smart Collection surface tests verify their source actions use the same `Open source record` control; the Roadmap and Smart Collection tests also reject the previous direct source links. The preview provider is mounted only in the authenticated founder shell, and its open target is held in component state. These checks bind preview behavior to the [Arama ve ilişki](../../prd/16-product-acceptance.md#uctan-uca-kabul-yolculuklari) acceptance journey without writing a source copy, collection membership, or persistent panel state. Notification Center has no implementation or route in this repository. Its integration is deferred to `docs/specs/72-personal-shell/`, which owns that UI surface and route; #268 covers the five existing consumers above.

- **Account Access failure counterpart.** `apps/web/e2e/client-shell.e2e.ts` verifies that a failed protected-route session check preserves the Client Shell error and its explicit `Retry` without rendering `Search` or crashing the page. After a successful retry with an authenticated Account, `Search` becomes available. Account Access owns session validation; discovery consumes only the successfully loaded authenticated route context.
- **What a good test is.** Tests observe Record Discovery through its public interface: query order, snippet, exclusions, indexes, table inline apply, preview without copy. They do not assert `pg_trgm` operator names or index DDL. Expected values are product rules (deterministic order, no AI, no secrets, Drafts absent).
- **Seam (one).** Record Discovery — search, prepared type indexes, type-scoped table, and in-context preview. Command Palette, Smart Collection membership, Documents authoring, and tag dictionary are counterparts, not this module.
- **Modules under test.** Record Discovery only. Palette commands, collection condition builder, and custom-field schema are out except as counterparts.
- **Prior art.** Contract tests at this seam with an index fixture that includes authorized and unauthorized records. Evidence environment for [Arama ve ilişki](../../prd/16-product-acceptance.md#uctan-uca-kabul-yolculuklari) is both real project and synthetic authorization counterparts. Cloud tests must not use production sessions, tokens, or private user content.
- **Required counterparts.** Draft/capture/external/secret absent; unauthorized Workspace cannot see names or counts; ranking ignores click history; Search ≠ Palette; folder browse on Document/File indexes does not replace Search; table disallowed types have no table; inline edit is not bulk edit; preview creates no record and is not a mandatory side panel; this feature does not create a Smart Collection.

## Out of Scope

- Anlamsal/AI sıralama veya gizli kişiselleştirme.
- Taslak, Yakalama öğesi, Dış yüzey snapshot'ı veya GitHub dış kaydını dizinleme.
- Secret, paylaşım token'ı veya bağlantı parolasını arama gerçeğine alma.
- Aramayı Komut Paleti ile tek yüzey sayma.
- Belge hiyerarşisini evrensel aramanın yerine koyma.
- Önizlemeyi ikinci kayıt veya düzenleme oturumu sayma.
- Paneli açık bırakıp kalıcı yerleşim kaydetme.
- Bütün kayıt türleri için zorunlu yan panel dayatma.
- Dizini ana menü başına tek tablo veya ayrı sahiplik kapsamı sayma.
- Kurulum gerektiren görünümü hazır dizin yerine koyma.
- Arşiv kayıtlarını dizinden düşürme veya silinmiş sayma.
- Tablo satırını ayrı kayıt veya dış spreadsheet senkronu sayma.
- Inline düzenlemeyi toplu eylemin yerine koyma.
- Türü desteklenmeyen kayıtlara tablo dayatma.
- Akıllı Koleksiyon üyelik koşullarını burada tanımlama; özel alan şeması (10).
