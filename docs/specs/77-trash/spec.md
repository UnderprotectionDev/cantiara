# Çöp Kutusu

Kaynak: [`docs/workflow/77-trash/phase-context.md`](../../workflow/77-trash/phase-context.md)

## Problem Statement

Kurucu desteklenen kaydı veya yapılandırma tanımını geri alınabilir biçimde kaldırmak, süre içinde aynı kimlikle geri yüklemek veya yüksek risk teyidiyle erken kalıcı silmek ister. Bugün Arşiv, gizleme filtresi, Proje kapanışı ve operasyonel yedek bu işi üstlenmiş gibi durabilir; Çöp Kutusu kimliği koruyan 30 günlük yaşam sınırı değildir. Dış yüzeyler sessizce yaşayabilir, Proje silme grubu çocuklara ayrı süre verebilir, erken kalıcı silme ayrı bir GitHub teyit kartı açabilir. Güvenlik redaksiyonu, Proje arşivi ve Hesap kapatma bu sorunun parçası değildir.

## Solution

Kurucu desteklenen ana kaydı ve yapılandırma varlığını `Trash`'e alır. Kayıt kimliğini korur; aktif kural ve görünüm üyeliği üretmez. Süre 30 gündür; süre sonunda kalıcı silinir. Çöp Kutusuna alma bağlı Dış yüzeyleri listeler ve varsayılan olarak iptal eder. `Keep approved surface` yalnız yaşayan Çalışma Alanı, Proje veya Kişisel Wiki içindeki tekil kaynakta, yalnız geri alınabilir sürede açıktır; Proje, Çalışma Alanı veya Hesap silmede sunulmaz. Proje silme grubu 30 günü tek birim izler. Erken kalıcı silme Hesap Erişimi feature'ının `Confirm GitHub Identity` grant'ini tüketir ve etkilenen Hesap veya Proje adının yazılmasını ister; ikinci teyit kartı açılmaz. Arşiv 83'tedir.

## User Stories

1. As a founder, I want to move a supported primary record to `Trash` and keep its internal identity, so that restore returns the same record rather than a copy.
2. As a founder, I want a trashed record to stop producing active rule, Smart Collection, or named-view membership, so that Trash is not a hidden working set.
3. As a founder, I want Trash retention to be 30 days, so that recoverable deletion has a single product clock.
4. As a founder, I want a record still in `Trash` to be restorable to the same ownership scope, so that restore is not a move to another Project or Workspace.
5. As a founder restoring, I want no automatic retargeting of broken relations to a "similar" record, so that identity is not silently rewritten.
6. As a founder previewing `Move to Trash`, I want every attached External Surface listed, so that I see the access effect before commit.
7. As a founder confirming that move, I want those External Surfaces revoked by default, so that a trashed source does not keep publishing.
8. As a founder deleting a single source inside a living Workspace, Project, or Personal Wiki, I want an explicit `Keep approved surface` choice during the recoverable window, so that a frozen last Approved Snapshot Revision can remain without live fields.
9. As a founder who kept an approved surface, I want that surface frozen on its last Approved Snapshot Revision and unable to publish new content or live fields, so that "kept" does not mean "still live".
10. As a founder who later restores that source, I want the kept surface not to rebind automatically, so that republish remains an explicit bind-and-approve step.
11. As a founder deleting a Project, Workspace, or Account, I want `Keep approved surface` absent, so that group deletion cannot leave visitor URLs alive.
12. As a founder, I want a Project delete group to share one 30-day clock, so that a child cannot permanently disappear while the Project is still recoverable.
13. As a founder, I want duration-end or early permanent delete to apply to the whole Project delete group, so that partial child permanent delete is impossible.
14. As a founder, I want Workspace, Account, and Personal Wiki records outside the Project not to be deleted with the Project, so that only canonically owned records enter the group.
15. As a founder looking at a living relation whose other end is in `Trash`, I want a deleted-target mark without leaked body or title the way a broken-reference contract requires, so that restore can reconnect the same identity later.
16. As a founder, I want a revoked External Surface itself to be movable to the ordinary 30-day `Trash`, so that surface records follow the same retention.
17. As a founder, I want permanent delete of a trashed record blocked while an active External Surface still uses it or sensitive content has not been removed, so that delete cannot outrun access shutdown.
18. As a founder, I want project-scoped custom fields, priority criteria, Smart Collections, named views, Prioritization sessions, automation rules, record actions, and templates to enter Configuration Trash under the same 30-day rules, so that definitions are not a second deletion product.
19. As a founder, I want a trashed configuration definition to stop running, so that a deleted automation or view cannot keep mutating or listing work.
20. As a founder previewing configuration delete, I want affected stored values and dependent views or rules shown, so that I see the blast radius.
21. As a founder restoring configuration, I want the same internal identity, definition, stored values, and resolvable dependencies back, so that restore is not a silent mint of a new definition.
22. As a founder restoring when a dependency was permanently deleted or changed meaning, I want a conflict preview rather than a silent retarget, so that identity stays honest.
23. As a founder who made a bulk wrong edit, I want Trash not to be offered as a restore-point library, so that I do not confuse recoverable delete with operator backup.
24. As a founder, I want early `Permanently Delete` before day 30, so that I can finish destruction without waiting out the clock.
25. As a founder starting that early delete, I want an effect preview, consumption of the Account Access `Confirm GitHub Identity` grant bound to this operation, and typing the affected Account or Project name, so that GitHub proof and name-typing stay distinct steps.
26. As a consuming feature, I want to call that grant instead of opening a second identity-proof card, so that OAuth/PKCE/`prompt=select_account` stay owned by Account Access.
27. As a founder, I want that GitHub step not copy-written as password, MFA, or session refresh, so that the UI tells the truth.
28. As a founder after permanent delete, I want the Denetim kaydı to keep only aliased identity, event type, time, and actor — never email, IP, content, or deleted field values — so that destruction is accountable without leaking.
29. As a founder, I want a content-free GitHub-record tombstone (provider, stable repository and source id, delete time, local alias only) to block automatic resurrection, so that a webhook cannot recreate the deleted local record.
30. As a founder (and as the operator restoring from backup), I want permanent delete to append a secret-free irreversible security event, so that an old database copy cannot resurrect the deleted record after replay.
31. As a founder using only a keyboard or a screen reader, I want to complete move-to-Trash, restore, and the early-delete confirmation (grant + typed name), so that the closed accessibility journey that includes Çöp Kutusu ve geri yükleme is possible.
32. As a founder, I want English UI copy `Trash`, `Move to Trash`, `Restore`, `Permanently Delete`, and `Keep approved surface`, so that the product language stays English.
33. As a founder, I do not want Trash to be Archive, a hide filter, Project retirement, Account closure, security redaction, or operator backup, so that each life-cycle boundary stays one product behavior.
34. As a founder, I want Test Oturumu and its Oturum Testi children to move, restore, and permanently delete as one historical whole, so that this seam does not invent a second test-lifecycle owner.
35. As a founder, I want a GitHub dış kaydı in `Trash` to stop receiving new source-status writes, so that Trash is not a live sync target (GitHub bağlantısı owns the sync adapter; this seam owns the life-cycle gate).

## Implementation Decisions

- **Owning documents.** Behavior is owned by [Çöp kutusu ve geri yükleme](../../prd/13-data-security-and-portability.md#cop-kutusu-ve-geri-yukleme) and [saklama ve güvenli silme süreleri](../../prd/13-data-security-and-portability.md#saklama-ve-guvenli-silme-sureleri). Project delete group membership and restore-to-Archive identity are [ortak yaşam döngüsü](../../prd/02-domain-model-and-lifecycle.md#ortak-yaşam-döngüsü); this feature owns the 30-day clock as one unit and the Trash/permanent-delete mechanics those rules call. External Surface revoke/keep effects on access, tokens, visitor sessions, and cache are executed through [ortak snapshot ve dış görünürlük güvenliği](../../prd/14-sharing-and-public-publishing.md#ortak-snapshot-ve-dis-gorunurluk-guvenligi); this feature owns when the move-to-Trash preview lists surfaces, defaults to revoke, and whether `Keep approved surface` is offered. Test-record whole-group semantics stay with [Test kayıtlarında arşiv, Çöp Kutusu ve kalıcı silme](../../prd/10-testing-and-validation.md#arşiv-çöp-kutusu-ve-kalıcı-silme); this seam applies the common Trash contract to that whole. GitHub-record write-stop and resurrection tombstone are triggered here and detailed in [GitHub geliştirme kayıtları](../../prd/12-github-and-project-releases.md#github-geliştirme-kayıtları). No new ADR: Archive vs Trash, surface identity, and restore replay are already decided.
- **Glossary.** Use Çöp Kutusu (`Trash`), Yapılandırma çöpü, Proje silme grubu, Silinmiş hedef işareti, Dış yüzey, Onaylı snapshot revizyonu, GitHub kimliğini yeniden teyit etme (`Confirm GitHub Identity`), Denetim kaydı, and Geri döndürülemez güvenlik olay günlüğü. Do not introduce User Workspace, recycle bin, hide filter, restore-point, or a second confirmation card. Proje arşivi is 83, not this feature. Güvenlik redaksiyonu is 78. Hesap kapatma is 84. Operasyonel yedek is 85.
- **Trash module.** Trash is the product-facing recoverable-deletion interface: move, list, restore, duration-end permanent delete, and early permanent delete. Record types do not each invent a Trash. Mutations use the common base-revision and idempotency contract (workflow 04); this feature does not re-specify that write envelope.
- **Identity and membership.** A trashed primary record keeps its internal identity and ownership scope. Owned components follow that owner into Trash; independent related records are not moved without confirmation. It does not join active automations, Smart Collections, or named views. Search, counts, and exports that require a living record omit it except on the `Trash` surface. Restore reconnects the same identity; living relations that showed a deleted-target mark resolve again. Test Oturumu and its Oturum Testi children are one historical whole (PRD 10 owns that rule; this seam applies the common Trash contract and must not trash a child alone).
- **30-day clock and Project delete group.** Ordinary records have a 30-day recoverable window, then permanent delete. A Proje silme grubu is one retention unit: children cannot permanently delete on a separate clock. Duration-end and early permanent delete apply to the whole group and remove contents; required content-free identity and audit marks may remain. Which records belong to the group is 02; this feature enforces the clock and the all-or-nothing permanent delete.
- **External Surfaces on move.** Move-to-Trash preview lists every attached External Surface and defaults to revoke (terminal: existing visitor sessions close; URL/token never reuse). `Keep approved surface` is offered only when (a) the source is a single record, (b) it lives in a living Workspace, Project, or Personal Wiki, and (c) the action is recoverable deletion — not Project, Workspace, or Account deletion. A kept surface freezes on its last Approved Snapshot Revision, cannot publish new content or live fields, and does not auto-bind when the source is restored. Permanent delete is refused while an active External Surface still uses the record or sensitive content has not been securely removed.
- **Configuration Trash.** Project-scoped custom fields, priority criteria, Smart Collections, named views, Prioritization sessions, automation rules, user-defined record actions, document templates, and work-item templates use the same 30-day move/restore/permanent-delete rules. A trashed definition does not run. Restore restores the same internal identity; a permanently deleted or meaning-changed dependency is previewed as a conflict, never silently rebound or reminted.
- **Early permanent delete consumes Account Access.** This feature owns effect preview, typed Account or Project name, and calling consume on the Account Access grant with this operation identifier. It does not start OAuth, PKCE, `prompt=select_account`, or mint the grant. It must not ship a second identity-proof card. GitHub-down fail-closed behavior is Account Access: if the grant cannot be consumed, early permanent delete is not applied. Access-reducing revoke of surfaces is not blocked by GitHub unavailability.
- **Audit and replay.** Permanent delete writes a Denetim kaydı event (365-day auth/authorization class) with aliased identity, event type, time, and actor only. It also appends a secret-free irreversible security event for restore replay. Content, secrets, emails, and IPs never enter logs or tombstones. GitHub-record tombstones carry provider, stable repository and source id, delete time, and local alias only, for as long as the canonical Project lives; after Project or Account permanent delete they follow the longest operational backup/restore window plus 30 days (85 owns that window).
- **English UI labels.** First user-visible copy: `Trash`, `Move to Trash`, `Restore`, `Permanently Delete`, `Keep approved surface`. `Trash` is already the glossary UI label; the others are added to the PRD term table in the same change that first shows them. Broken-reference reason copy shown from this surface uses English (`In Trash`, `Permanently deleted`) when this feature is the first to show them. No Turkish UI.
- **Not Archive.** Record-level or Project Archive is not implemented here. A founder cannot use Trash to make a Project read-only. Workflow 83 owns Archive and "delete only from Archive as one group"; when that group enters Trash, this feature's clock and surface-revoke rules apply, including the ban on `Keep approved surface`.

## Testing Decisions

- **What a good test is.** Tests observe Trash through its public interface: move, preview (including External Surface list and `Keep approved surface` eligibility), restore, configuration-inactive, duration-end permanent delete, early permanent delete (grant consume + typed name), and whether a protected command is authorized. They do not assert Prisma row shapes or mock private collaborators. Expected values are product rules (30-day unit, identity preserved, no active membership, grant missing fails closed, typed-name mismatch fails closed), not recomputed implementation.
- **Seam (one).** Trash — the product-facing recoverable-deletion interface used by record UIs, Configuration Trash, Project delete group retention, and early permanent delete. External Surface revoke/keep, Account Access grant consume, and the security-event log are adapters behind that interface (real versus test double). Playwright for the closed accessibility journey that includes Çöp Kutusu ve geri yükleme is the same seam observed through the UI, not a second product module.
- **Modules under test.** Trash only. Project Archive (83), security redaction (78), Account closure (84), operator backup RPO/RTO (85), and GitHub App sync internals are not in this suite except as counterparts: Archive is a different command; redaction is not Trash; grant missing cannot permanently delete; restore-point library absent; GitHub-record in Trash refuses new source writes via the life-cycle gate.
- **Prior art.** Account Access (`docs/specs/01-account-access/`) is the grant to consume with a test double — do not copy OAuth/PKCE tests here. Mutation/idempotency is workflow 04; Trash tests assume that envelope and assert Trash outcomes. Synthetic fixture is the evidence environment for [Proje silme ve dış yüzey](../../prd/16-product-acceptance.md#uctan-uca-kabul-yolculuklari) and the Mutasyon sözleşmesi journey's delete/restore slice. Cloud tests must not use production sessions, tokens, or private user content.
- **Required counterparts.** `Keep approved surface` absent on Project/Workspace/Account deletion; present only for living single-source recoverable delete; kept surface does not auto-bind on restore; Project delete group children cannot permanently delete on their own clock; configuration in Trash does not run; restore does not mint a new identity; early delete without grant or without matching typed name does not write; Trash is not offered as Archive or restore-point; Test Oturumu children cannot be trashed alone; GitHub-record in Trash does not accept new source-status writes.

## Out of Scope

- Proje arşivi, arşivden çıkarma, Arşiv güvenlik istisnası ve "silme yalnız Arşivden" — 83.
- Güvenlik redaksiyonu UI'si ve yayılım sözleşmesi — 78; kalıcı silme hassas içeriği kaldırmadan engellenir, redaksiyon motoru burada yazılmaz.
- Hesap kapatma penceresi, kapanma dondurması, Çalışma Alanı çıkış paketi — 84 ve 82.
- Operasyonel yedek, kullanıcı restore-point'i, RPO/RTO — 85.
- `Confirm GitHub Identity` OAuth/PKCE turu, grant mint ve callback — Hesap Erişimi (01); bu feature yalnız consume eder.
- Dış yüzey oluşturma, ziyaretçi oturumu, cache purge mekaniği — 14 / 76; bu feature tetikler.
- GitHub App kurma, webhook inbox, uzlaştırma UI — 61; bu feature yalnız Çöp kapısını koyar.
- Güvenli geri alma yığını, genel undo — 04.

## Further Notes

- **Orient.** Glossary: Çöp Kutusu, Yapılandırma çöpü, Proje silme grubu. Owning PRD: `docs/prd/13-data-security-and-portability.md` (`#cop-kutusu-ve-geri-yukleme`). ADRs in play: none new; 0001/0002 (surface vs snapshot and access cutoff), 0003/0019 (permanent-delete replay event type; 85 owns the store and RPO/RTO). Related: PRD 02 (group invariant, broken references), PRD 03 (grant owned by Account Access), PRD 04 (Archive is 83), PRD 10 (test whole-group), PRD 12 (GitHub-record Trash gate), PRD 14 (revoke/keep access effect), PRD 15 (a11y; Archive vs Trash must not be written onto each other), PRD 16 (journeys), PRD 19 (no user restore-point library).
- **Acceptance.** Bind this feature to [Proje silme ve dış yüzey](../../prd/16-product-acceptance.md#uctan-uca-kabul-yolculuklari) (synthetic fixture: Project enters Trash → all project-scoped surfaces and visitor sessions terminal-revoked; restore does not republish; single-source keep freezes and does not auto-bind) and to the closed manual accessibility journey **kayıt oluşturma, düzenleme, çatışma, geri alma, Çöp Kutusu ve geri yükleme**. Mutasyon sözleşmesi covers the write envelope of move/restore, not Trash rules. Negative bounds (Trash is not Archive, not restore-point, not redaction, no second GitHub card, `Keep approved surface` forbidden on Project deletion) are 19-class counterparts on those journeys.
- **Consumers.** Workflow `83-project-retirement` puts a Project delete group into this clock and must not offer `Keep approved surface`. Workflow `84-account-closure` is not Trash. Early permanent delete consumes `01-account-access` grant. Permanent-delete events are replayed by `85-operator-backup-and-alarms`.
- **Grant rule.** Typed-name confirmation stays in this feature. Do not re-specify OAuth/PKCE. Call the Account Access grant.
