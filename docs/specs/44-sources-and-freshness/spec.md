# Kaynaklar ve Kanıt Tazeliği

## Problem Statement

Kurucu dış bilginin kimliğini, kökenini ve tarihli sürümünü canlı sayfa gibi kaybetmeden tutmak ister. Önizleme iç ağı açarsa veya HTML ikinci doğruluk kaynağı olursa ürün güvenilmez. Yeniden kontrol kullanımları sessizce yeni sürüme taşırsa eski kanıt yalan söyler. Uzun gövde feed’i Geri Bildirim feature’ındadır. Kaynağın varlığı otomatik Kanıt bağı değildir.

## Solution

Kaynak Proje ana kaydıdır; URL/başlık, erişim zamanı, yakalanan içerik ve tarihli sürümler. Akıllı bağlantı önizlemesi ADR-0008 yalıtılmış egress ile başlık/alan adı/güvenli görseldir; dış HTML gömülmez. Canlı oynatıcı yalnız YouTube’dur, tıklanınca yüklenir, autoplay yoktur. `Recheck source` aday snapshot üretir, onaylı sürümü kendiliğinden değiştirmez; her kullanım kendi `Keep current version` veya `Rebind to new version` kararını verir. Toplu “hepsini güncelle” örtük çalışmaz.

## User Stories

1. As a founder, I want a Source with address, title, access time, and captured content, so that an outside page is a dated record, not a live mirror.
2. As a founder, I want short excerpts, screenshots, and attachments on the Source, so that origin is inspectable.
3. As a founder, I want optional provider, external record type, and external id only when URL shape or my explicit entry resolves them, without credentials, sync, or turning the URL into Work.
4. As a founder, I want a new fetch not to delete an old Source version, so that historical capture stays.
5. As a founder pasting a public HTTP(S) URL, I want a scannable preview of title, domain, and optional safe image, without that preview itself creating a Source.
6. As a founder, I want preview to refuse other protocols, private/link-local/loopback/reserved targets, >20 MB responses, and executable content, leaving a safe text link.
7. As a founder, I want preview and recheck to run on an unprivileged egress path that re-validates DNS and every redirect (ADR-0008), with no user credentials or session cookies.
8. As a founder, I want `Save as Source` to turn a preview into a Source, visually separating live preview from the historical snapshot.
9. As a founder, I want YouTube as the only live player: labeled `Live external source`, click-to-load, no autoplay, original URL visible, third-party warning remaining; removed/private/age/region-restricted videos fall back to a safe link plus error, not a broken embed.
10. As a founder, I want a YouTube card not to be historical evidence; once saved as Source, live player and captured-at-access content stay distinct.
11. As a founder, I want Vimeo and other providers to stay safe rich previews, never players; pasted iframe/embed code refused.
12. As a founder, I want `Recheck source` to preview the address, current approved version, and that a third-party fetch will occur, with no background polling or time-only refresh.
13. As a founder, I want each check to store a dated Source Check event (time, user, start and final URL, HTTP result, content type, fingerprint) and, on success, a sanitized candidate snapshot that does not become the approved version by itself.
14. As a founder, I want failure (auth, deleted, blocked, unsupported) not to display old content as current; the failure stays on the event.
15. As a founder, I want side-by-side compare, and line/section diff when structure allows, including missing pin matches shown as `No match in candidate version` without silent semantic rebind.
16. As a founder, I want `Keep current version` to keep the check in history without changing the approved Source version.
17. As a founder, I want `Save as new Source version` after preview to add a version; old version and its Decision/Work/Feedback pins stay; the new version does not inherit binds or create Work/Risk/Test Gap.
18. As a founder, I want each evidence use to show exact Source version, access date, and range, plus `Newer Source version exists` with compare, without labeling the old version silently false.
19. As a founder, I want per-use `Reviewed; keep current version` or `Rebind to new version` with preview of only that bind; other uses keep their own decision. No implicit update-all.
20. As a founder, I want `source-version-in-use` when a newly approved version still has active evidence binds on older versions, grouped per Source, each use separate; ordinary `İlgili`, live card, or viewing does not emit it; Source age or failed check alone does not.
21. As a founder, I want recheck not to be a gate or auto impact analysis: unread new versions do not write Work/Decision/Risk/test/Release status.
22. As a founder, I want Source Check events not to appear as independent Universal Search hits that duplicate current Source body.
23. As a founder, I want share/publish to preview candidate, diff, and each new version as separate closed-world items; an old public snapshot does not change because of a new check.
24. As a founder, I want English UI `Source`, `Save as Source`, `Recheck source`, `Keep current version`, `Save as new Source version`, `Newer Source version exists`, `Reviewed; keep current version`, `Rebind to new version`, `Live external source`, `No match in candidate version`.
25. As a founder using only a keyboard or a screen reader, I want to save a Source, run recheck, compare, and decide per use.
26. As a founder, I do not want this feature to own the long-body Feedback/Source Feed (47) or to treat Source presence as an evidence bind (45).
27. As a consuming attention center (71), I want `source-version-in-use` production rules to stay here.

## Implementation Decisions

- **Owning documents.** [Kaynak kaydı](../../prd/08-search-relations-and-evidence.md#kaynak-kaydı-ve-köken-bilgisi), [Akıllı bağlantı önizlemesi](../../prd/08-search-relations-and-evidence.md#akıllı-bağlantı-önizlemesi), [Kaynağı yeniden kontrol etme](../../prd/08-search-relations-and-evidence.md#kaynağı-yeniden-kontrol-etme-ve-sürüm-karşılaştırması), [Bilgi güncelliği](../../prd/08-search-relations-and-evidence.md#bilgi-güncelliği). Isolation: [ADR-0008](../../adr/0008-dis-url-onizleme-yalitimi.md). Tech: `undici`, `htmlparser2`, `ipaddr.js`, `diff` (jsdiff). Signal `source-version-in-use` registry in PRD 04; production here. Feed body: 47. Evidence binds: 45. No new ADR.
- **Glossary.** Use Kaynak, Akıllı bağlantı önizlemesi, Kanıt bağı (do not auto-create), Dikkat sinyali. Avoid bookmark, live web mirror, preview-as-Source, Vimeo player.
- **Source module.** Project-scoped versions; new fetch does not delete old. Helper: Source Check event + candidate snapshot. Approved version changes only on explicit save.
- **Source records foundation (#330).** `packages/api/src/sources-and-freshness.ts` owns Source identity, dated plain-text capture contracts, HTTP(S) scheme normalization that preserves path/query/fragment bytes, and explicitly entered optional provider/external type/id. `source` owns Project identity and current revision; append-only `source_version` rows own each URL, title, access time, exact captured text, provenance and save time. `createSource`, `saveSourceVersion`, `source`, and `projectSources` are authenticated oRPC entrypoints backed by the existing atomic/idempotent mutation adapter. Reads return chronological versions; archived Projects remain readable and reject writes. This foundation has no browser surface, fetch, candidate approval UI, credentials, sync, Work conversion, or evidence creation. Preview/recheck adapters remain separate follow-up work. Tests: the #330 Sources and Freshness contract below.
- **Preview adapter.** Separate unprivileged egress. DNS and redirect re-check every hop; block loopback/private/link-local/reserved; HTTP(S) only; no credentials; tight redirect/time/byte/CPU limits; sanitize; fail to plain link. YouTube click-to-load iframe only after explicit click and visible third-party warning; no autoplay. No other live player. No user iframe paste.
- **Isolated Smart Link Preview (#331).** `smartLinkPreview` is an authenticated, non-persistent RPC. The product API contacts only a configured HTTPS `SMART_LINK_EGRESS_URL`; an absent/unavailable service leaves a plain link and never falls back to fetching inside the application network. A separate Railway service (`apps/server/src/smart-link-egress.ts`) owns credential-free workers, per-hop public DNS validation and pinned connections, bounded parsing and recompressed WebP images. Deploy it outside the product private network with no secrets, non-root execution and memory/edge limits; the operational contract is [egress-operations.md](egress-operations.md). `apps/web/src/features/sources-and-freshness/` is consumed in Project `Discovery`: pasting in `Source URL` requests a transient `Live preview`; `Preview` explicitly retries. `Save as Source` writes the displayed dated capture through #330, and saved records show `Historical snapshot` separately. A failed preview cannot save unverified capture data. YouTube uses bounded oEmbed metadata rather than its executable page shell; only its title is captured, with explicit copy that playback remains live. `Load YouTube` loads the official IFrame API after click, uses the privacy-enhanced host and autoplay 0, and removes unavailable players on provider error or timeout while retaining the original URL and third-party warning. Vimeo and pasted embed code never produce players. No schema changes, periodic polling, recheck, new version approval or evidence binds are introduced. Tests: #331 preview contract below.
- **Review corrections (#331).** Preview and saved Source access times use the current Account Preferences (`Locale`, `Time zone`, `Date format`) through `formatAccountDateTime`; the stored capture instant is unchanged. Packaged macOS uses a static product-API HTTPS document at `/smart-link/youtube/:videoId`, requested only after `Load YouTube`, to supply [YouTube's required HTTP Referer](https://developers.google.com/youtube/terms/required-minimum-functionality#embedded-player-api-client-identity). It accepts only an 11-character YouTube id, does not resolve/fetch user URLs or read account data, and uses nonce CSP, privacy-enhanced playback and `strict-origin-when-cross-origin`. The local surface accepts readiness/error messages only from that iframe and configured API origin for the selected video; errors/timeouts remove playback while retaining the original link/warning. Web retains the official direct IFrame API. Tests: the #331 review corrections contract below.
- **Source Check, candidate approval and per-use review (#332).** `packages/api/src/source-recheck.ts` and `server/source-recheck-database.ts` own user-started `recheckSource`, Source-owned check history, and explicit keep/approve decisions. Egress supplies actual HTTP result, final URL and content type; missing result metadata fails closed instead of fabricating a successful capture. Each check preserves its actor, start time, exact compared Source revision, sanitized candidate and content fingerprint. The Source Check mutation adapter serializes with Project archive and Source saves through ADR-0004; approving a candidate appends exactly one Source version in the same transaction, retains old captures, rejects stale decisions, and replays identical retries. Project Discovery opens `Source Check` history and fetch preflight locally; only `Recheck source` contacts the third party. Comparison uses the exact historical baseline and candidate, account date formatting, side-by-side snapshots and bounded jsdiff line comparison. Failed checks never display historical text as a current capture. No background scan, status change, evidence creation, or bulk update is introduced. `source-evidence.ts` exposes authenticated exact-version bind previews and per-use keep/rebind through the Evidence writer. Every commit rebuilds the displayed pin and target under canonically ordered Project locks and rejects a changed Source, bind, target or preview payload. Project Discovery shows each use’s version, access date, UTF-16 range and `Newer Source version exists`; a missing or ambiguous literal match is `No match in candidate version`, and selecting a replacement range requires a fresh preview. Evidence revision, reviewed Source revision, actor and time are saved atomically with mutation history. `source-version-in-use` is derived once per Source from accessible active older binds not yet reviewed against the latest approved version; a keep decision preserves its old pin and clears only that use from the group. No Center UI is delivered here. Tests: #332 recheck and per-use contract below.
- **Recheck.** User-started only. Per-use rebind via 45’s explicit rebind; this feature must not batch-rebind. `source-version-in-use` when new approved version × remaining old binds; closes when every use is reviewed. Not a gate.
- **English UI labels.** As in stories. Add when first shown.
- **Consumers.** 71 presents the signal. 47 feed reads the same Source body. 45 owns Kanıtı relation.

## Testing Decisions

- **What a good test is.** Tests observe Sources and Freshness through Source CRUD, isolated preview, recheck/compare, and per-use keep/rebind. They go red on silent rebind, private-IP preview success, or treating preview HTML as a Source version. Expected values come from the freshness journey (one Source, three targets, two versions, partial review), not from fetch implementation.
- **Seam (one).** Sources and Freshness — Source CRUD, preview, recheck/compare, per-use decision, signal production. Egress is an adapter (real vs double that still enforces deny-private).
- **Modules under test.** Sources and Freshness only. Evidence rebind and Notification Center are consumers/counterparts.
- **Prior art.** First contract tests at this seam with an egress test double. Journey: [Kanıt tazeliği](../../prd/16-product-acceptance.md#uctan-uca-kabul-yolculuklari). Adversarial preview: private IP, redirect-to-private, oversized, non-HTTP.
- **Required counterparts.** Preview is not a Source; YouTube-only player; no silent rebind; no update-all; Source existence is not Kanıtı; feed UI absent; no background poll.
- **#330 Source records contract.** `packages/api/src/sources-and-freshness.test.ts` and `server/tests/sources-database.integration.test.ts` exercise this same seam through capture commands, authenticated RPC and PostgreSQL reads. They preserve two dated versions including exact whitespace and old provenance; mixed-case HTTP(S) schemes are normalized before both create and version saves, preserving case-sensitive path/query/fragment; verify explicit new-version saves, identical retry, changed-payload conflict, stale/concurrent saves, Project/Account isolation, archive read-only behavior, and unchanged Relations/usage-link counterparts. The fixture database is disposable local PostgreSQL; development preparation is separately verified by `db:prepare` and the post-test `db:doctor`. This foundation adds no browser journey; the freshness journey's three evidence targets, preview/recheck and per-use review remain later ticket counterparts.

- **#331 preview contract.** `server/tests/smart-link-preview.test.ts` observes transient metadata, denied private/reserved/mixed DNS answers and rebound/redirected targets, credentials/iframe/non-HTTP rejection, oversize/compression/executable fallback, optional image failure, and exact YouTube-only player ids with a network double that still passes through the real security policy. `smart-link-preview-gateway.test.ts` observes URL-only egress requests and missing-service, mismatched-URL/player, invalid-output and oversized-result fallbacks. `sources-database.integration.test.ts` calls authenticated preview and Source RPCs: preview creates no record, explicit save pins the access-time text, later outside changes leave that version untouched, and anonymous calls fail. `ui/components/tests/smart-link-preview.test.tsx` uses the preview and YouTube API boundaries to verify explicit save, no iframe/script before click, autoplay 0 and player removal on restriction without losing the link/warning. `apps/web/e2e/smart-link-preview.e2e.ts` observes the same seam through Project Discovery, keyboard save, browser reload persistence, private-redirect fallback, YouTube-only click controls and an accessibility audit. Doubles do not prove deployed network isolation or live YouTube availability; deployment prerequisites are explicit in the operational contract.

- **#331 review corrections contract.** The composer test verifies Istanbul/New York capture display, preference changes, the unchanged instant passed to `Save as Source`, native click-to-load, forged message rejection, readiness, restrictions and timeout fallback. `project-sources-surface.test.tsx` observes saved snapshots with both preference sets through the Query read boundary. `youtube-player-page.test.ts` observes the public Hono route, invalid ids and nonce CSP; sandboxed Chromium/WebKit provider doubles verify an actual HTTPS Referer header and readiness/restriction delivery. These adapter tests require no database; live packaged WKWebView playback and production HTTPS routing still require manual verification.

- **#332 recheck and per-use contract.** `smart-link-preview.test.ts` exercises the existing real public-network policy through a transport double, observing final URL/HTTP metadata and failure without current content. `sources-database.integration.test.ts` observes authenticated Source/recheck RPCs and PostgreSQL access: candidate persistence without automatic approval, exact baseline, identical retry, explicit approval with both captures preserved, YouTube video URL retained separately from its oEmbed fetch metadata, account isolation, anonymous rejection, stale revision conflict, failed approval rejection, keep without a new version, and archived read-only behavior. `source-check-compare.test.tsx` verifies distinct historical/candidate snapshots, added/removed line labels and missing-pin presentation; `source-recheck-controls.test.tsx` verifies visible URL/version/third-party preflight and no external fetch until explicit recheck. `source-evidence-database.integration.test.ts` observes the three-target/two-version/partial-review journey, unchanged target lifecycle, exact pin preservation on approval, per-use keep/rebind, grouped signal closure, authenticated access, forged/stale preview and retry conflicts, concurrent decisions, archive read-only behavior, and deleted-target Project tombstones retained without content leakage or active signals through the Sources and Freshness seam. `apps/web/e2e/source-recheck.e2e.ts` observes keyboard text selection and bind preview for Work/Decision/Feedback, keyboard-initiated fetch, exact old/candidate comparison, missing pins, explicit approval, per-use keep/rebind, partial signal closure, reload persistence and accessibility through Project Discovery. It runs independent fixtures twice; the capture transport is keyed by fixture URL, so a reused server cannot leak capture order across journeys; the adjacent preview journey stays a counterpart. Existing preview, saved Source and player tests remain counterparts. Local PostgreSQL verifies persistence; `db:prepare` and post-test `db:doctor` separately verify the shared development targets. These tests do not establish deployed egress isolation or live provider availability.

- Vimeo/diğer canlı oynatıcı, iframe yapıştırma.
- Periyodik tarama, zamanlı staleness, otomatik yenileme.
